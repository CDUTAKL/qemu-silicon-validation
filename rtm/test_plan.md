# 测试计划 — QEMU 虚拟板卡硅后验证框架

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 需求基线 | `rtm/requirements.yaml` (FR-01~09, NFR-01~06) |
| 追踪工具 | `rtm/rtm_report.py` |
| 状态 | 草稿 → 评审中 |

## 1. 测试范围与对象

被测对象 (DUT) 为运行于 QEMU 虚拟板卡 (`-M stm32vldiscovery`, Cortex-M3)
上的 FreeRTOS 固件，包含 Sensor / Comm / Diag / Watchdog 四个应用任务，
经 UART 以二进制帧协议 (AA 55 帧头 + CRC-16/CCITT) 上报遥测数据、心跳与
故障告警，并接收文本诊断命令。本计划覆盖设计文档 §3.1 全部功能需求
(FR-01~FR-09) 与 §3.5 非功能需求 (NFR-01~NFR-06)，共 15 条；不在范围内
的有：固件业务算法正确性、QEMU 仿真器自身的正确性、真实硬件电气特性。

## 2. 测试环境

- 仿真平台：QEMU 11.x，`stm32vldiscovery` 机器模型，UART 经 pty 导出
- 控制通道：QMP (stop/cont/system_reset/info registers)，自实现 asyncio
  客户端 (`harness/qmp.py`)
- 数据通道：pyserial 打开 pty，`harness/uart.py` 状态机按字节分流文本
  回显与二进制帧
- 执行框架：pytest + pytest-html/junitxml，固件由 `harness/fixture.py`
  一键拉起；统计断言由 `harness/asserts.py` 提供 (序号连续性/响应时间
  分位数/周期统计)
- 故障注入：诊断命令 (`inject`/`fault` 系列) 软件激励为主

## 3. 测试分级

五组用例对应硅后验证的典型层级，设计意图各不相同：

- **BOOT (TC-BOOT-001~005)**：上电/复位自举。先证明 DUT"能活"，是其余
  一切用例的准入前提，覆盖 NFR-01/02/03/06。
- **FUNC (TC-FUNC-001~010)**：正常工况功能验证——周期上报、序号连续性、
  心跳、ACK 握手、诊断命令，对应 FR-01~05，属需求主体。
- **FLT (TC-FLT-001~010)**：故障注入与告警验证。注入过压/过流/畸形帧等
  异常激励，验证 FR-06 告警链路与 NFR-05 健壮性，是硅后验证的核心价值
  所在 (异常路径在真硅上最难构造)。
- **RCV (TC-RCV-001~005)**：异常恢复——断线重连、任务挂起/恢复、看门狗
  复位后的行为一致性，覆盖 FR-07~09。
- **BM (TC-BM-001~004)**：时序与性能量化——告警响应时间、ACK 往返、
  启动时间，覆盖 NFR-04/06，输出 p50/p95/p99 分位数而非单点值。

## 4. 需求追踪方法

采用双向追踪的需求追踪矩阵 (RTM)：需求在 `rtm/requirements.yaml` 中唯一
定义；每条用例 docstring 标注其验证的需求 ID；`rtm/rtm_report.py` 静态
扫描用例源码 (ast 解析)、合并 pytest junit 结果，自动生成
`report/rtm.md`/`rtm.json`，给出需求覆盖率、用例通过率、缺口清单。缺口
为零是准出硬条件；任何需求变更须先改基线文件再补用例。

## 5. 准入与准出标准

**准入 (Entry Criteria)**：① 固件可编译并通过 `harness` 自测；
② QEMU/QMP/串口通道联通 (TC-BOOT-001 通过)；③ 需求基线冻结。

**准出 (Exit Criteria)**：① 需求覆盖率 100% (RTM 零缺口)；
② must 级需求关联用例全部 PASS；③ should 级用例通过率 ≥ 90%，失败项
有书面偏差说明；④ 无未解释的固件复位或 Lockup；⑤ RTM 报告与覆盖率
摘要归档。

## 6. 风险与局限

虚拟平台是真实硅后验证的方法学预演，二者边界必须声明：① 时序为仿真
时序，NFR-04/06 的绝对数值不能直接外推到真硅，但统计方法与判据框架可
复用；② QEMU 外设模型是理想化的，不覆盖时钟漂移、电压裕量、EMI 等
物理层问题；③ 故障注入以软件命令激励，不等价于激光/重离子等物理注入；
④ 仿真无 JTAG/SWD 调试器竞争问题，寄存器现场读取 (NFR-02) 的侵入性与
真机不同。上述局限不影响功能与协议层需求 (FR 系列) 的验证结论有效性。
